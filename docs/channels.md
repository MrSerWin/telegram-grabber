# Настройка каналов

Список каналов для скрапа и параметры задаются в `channels.yaml` в корне
репозитория. Этот файл в `.gitignore` — ваш список каналов не попадает в
репозиторий. Начните с шаблона:

```bash
cp channels.example.yaml channels.yaml
```

## Формат `channels.yaml`

```yaml
channels:
  - example_channel        # имя без @, как в адресе t.me/s/<name>
  - another_channel

delay: 1.0                 # сек между страницами (не опускай ниже 1)
max_pages: 1000            # потолок пагинации (~20k постов)
```

- **`channels`** — обязательный список. Имя канала берётся из его публичной
  ссылки `https://t.me/<name>` (то же, что `t.me/s/<name>` для веб-превью),
  без `@`.
- **`delay`** — пауза между запросами страниц. Скрапер ходит по чужому
  серверу; держите вежливую задержку ≥ 1 сек.
- **`max_pages`** — ограничение на число страниц пагинации. Поднимите, если
  канал крупнее ~20k постов.

Путь к конфигу можно переопределить переменной `TG_CONFIG`:

```bash
TG_CONFIG=/path/to/my-channels.yaml tg-grabber scrape
```

Явно переданные в командной строке каналы переопределяют конфиг:

```bash
tg-grabber scrape some_channel other_channel
```

## Что попадает в архив

Для каждого канала создаётся `out/archives/telegram_<channel>.json` —
массив постов. У каждого поста: `id`, `channel`, `url` (постоянная ссылка),
`datetime`, `text`, `links` (URL'ы из текста), `images` (URL'ы фото и
video-thumbnails), `views`, `forwarded_from`. Подробный формат — в
[README.md](../README.md#формат-архива).

Команда `tg-grabber media` затем скачивает фото из архивов и пишет
`out/media/manifest.json` с атрибуцией каждого файла к каналу и посту.

## Что НЕ скачивается (известное ограничение)

Веб-превью `t.me/s/` отдаёт только текст + фото-превью. **Документы**
(PDF, EPUB), **видео-файлы** и **аудио** не присутствуют в HTML канала —
это не баг скрапера, а ограничение публичного интерфейса Telegram. Чтобы
их забрать, нужен Telegram MTProto API (Telethon/Pyrogram) с авторизацией
пользователя.

URL'ы внешних ресурсов, упомянутых в постах, сохраняются в поле `links`
каждого поста — оттуда их можно тянуть отдельно простыми HTTP-запросами.
